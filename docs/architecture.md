# 法律助手（Legal Assistant）Agent 架构设计文档

> 版本 v1.0 ｜ 2026-09-02 ｜ 基于《深入理解 AI Agent》的核心公式 **Agent = LLM + 上下文 + 工具** 落地
> 本项目的技术主线：**Agentic RAG + 分层记忆 + MCP 工具 + 知识图谱可视化**

---

## 0. 项目定位

| 维度 | 决策 |
|---|---|
| 目标用户 | 普通老百姓（答案必须"大白话 + 给结论 + 强免责"） |
| 任务形态 | 一期：法律问答 + 法规/案例检索归纳；二期：合同审查 |
| 法域 | 仅中国大陆现行有效法 |
| 数据来源 | 官方公开库（国家法律法规数据库等） |
| 核心能力 | Agentic RAG（多轮检索）+ 混合检索 + GraphRAG 图谱 + 分层记忆 |
| 引用溯源 | 必须——答案强制标注"依据《XX法》第 X 条"并附原文 |
| 模型 | deepseek-v4-pro（主）、GLM-5.3（备）、flash（轻任务） |
| 安全 | 暂不加强门控，但保留引用溯源 + 免责声明（软门控） |

## 1. 总体架构：五层 + 一个横切基础设施

```
┌────────────────────────────────────────────────────┐
│ ① 前端页面层  frontend                            │  流式对话、引用法条高亮、知识图谱可视化("可查看")
├────────────────────────────────────────────────────┤
│ ② 接入/网关层  gateway                            │  WebSocket/SSE 流式、鉴权、会话管理、多 LLM 路由
├────────────────────────────────────────────────────┤
│ ③ Agent 推理层  agent（大脑）                     │  ReAct 循环、Agentic RAG 编排、记忆装配
│      ├─ 记忆模块 memory（L0-L3）                   │
│      └─ 编排器 orchestrator（单 agent，预留多 agent 边界）│
├────────────────────────────────────────────────────┤
│ ④ 工具层  mcp_tools（手）                         │  legal_search 检索工具、法律计算器、联网检索...
│      └─ 通过 MCP 协议暴露，可插拔、可复用          │
├────────────────────────────────────────────────────┤
│ ⑤ 知识/数据层  knowledge（料）                    │  采集管道、分块、向量+BM25+图谱三索引、重排序
│      ├─ 向量库 / BM25 / 知识图谱(Neo4j)            │
│      └─ 增量更新管道（RAG 要能更新）               │
└────────────────────────────────────────────────────┘
        ↑ 横向贯穿：评测集 / 配置 / 日志 / 可观测性
```

**一句话记法**：③ 是大脑，④ 是手，⑤ 是料（知识库），② 是门，① 是脸。

**关键解耦**：
- ④ 和 ⑤ 是两层不是一回事。④ 的"检索工具"是 agent 调用的**入口**，内部**向下调用** ⑤ 的检索能力。
- 换 embedding、改分块、重建图谱，都在 ⑤ 内完成，③④ 完全无感。
- 记忆放 ③ 内部：L0 是运行时上下文，L1/L2 是记忆存储，L3 知识库就是 ⑤。

## 2. Agentic RAG 设计（核心技术）

### 2.1 核心思想：多轮编排（③） × 单次检索（⑤）

| 职责 | 谁来做 | 落在哪层 |
|---|---|---|
| 多轮编排：查什么、查几轮、够不够、要不要换 query | Agent | ③ Agent 推理层 |
| 单次检索：一个 query → top-k 法条 | 检索器 | ⑤ 知识/数据层 |

⑤ 只负责"一次 query 进去 → 精确结果出来"，不关心第几轮；③ 负责"这轮不够，换问法再来"。

### 2.2 检索循环（四组件）

```
用户口语
  → ① 改写器 Rewriter：口语→法律检索式 + 子问题分解（LLM）
  → ② 检索器 Retriever：通过 MCP 调 ⑤ 混合检索（向量+BM25+图谱+rerank）
  → ③ 评估器 Critic：证据够不够回答？（flash 轻量模型判，省钱）
        ├─ 不够 → 换 query / 换检索策略 → 回到 ② （最多 5 轮）
        └─ 够   → ④ 生成器：写答案 + 强制引用溯源
```

组件落位：**改写器、评估器、生成器在 ③；检索器是 ④ 的 MCP 工具（向下调 ⑤）**。

### 2.3 多跳与策略切换（法律场景特有）

- **多跳检索**：命中 A 法条后，沿图谱边查"A 引用的、修订 A 的"法条（如 1153 条 ↔ 1062 条）。
- **策略切换**：语义检索没命中 → 切 BM25 精确匹配法条号；单条不够 → 切 GraphRAG 图谱扩散。
- **终止条件**：证据充分 / 达最大轮数（5）/ 确认查不到 → 进入"建议咨询律师"。

## 3. 混合检索 + GraphRAG

### 3.1 单次检索流水线（在 ⑤ 内）

```
query 进入 ⑤
  → 三路并行检索：
      ① 语义向量（dense）：智谱 embedding-3（直连）或 bge-m3（本地 modelscope）
      ② 关键词 BM25（sparse）：精确命中"法条号 / 术语 / 地名"
      ③ 结构化图谱（GraphRAG）：法条层级、引用、修订关系
  → RRF 倒数排名融合
  → 重排序（rerank）：LLM 判相关性（省去单独部署 rerank 模型）
  → 返回 top-k 法条 + 图谱子图
```

法律场景 **BM25 不可省**：精确匹配"法条号/术语"（抚养费 vs 抚养权）是纯向量的盲区。

### 3.2 GraphRAG 定位与图谱 schema

- **Local Search**：从一条法条扩散到邻居（"这条法条还跟哪些规定/判例相关"）。
- **Global Search**：社区聚合，回答"某领域法律体系全貌"这类宏观问题。
- **"可查看"**：图谱存 **Neo4j**（自带可视化），前端叠 ECharts graph 展示层级/关联。

图谱节点与边：
- 节点：法律、章、条、款、项、司法解释、判例、法律概念/术语
- 边：属于（层级）、引用（A 条引用 B 条）、修订（新法替代旧法）、适用于（法条↔案件类型）、同义/上位概念

### 3.3 分块策略

法律文本以 **"条"为最小完整单元**：先按条切，再把语义相关的相邻条合并成一个 chunk——既保语义连贯，又保条号边界可追溯。

## 4. 分层记忆 L0–L3

| 层 | 类型 | 内容 | 生命周期 | 技术 |
|---|---|---|---|---|
| L0 工作记忆 | 会话内·易失 | 当前对话 + ReAct 轨迹 + 本轮命中法条 | 窗口满即淘汰/摘要 | LLM 上下文 |
| L1 情景记忆 | 短期·可压缩 | 会话摘要、问题脉络 | "接着聊"复用 | 摘要存本地 |
| L2 语义记忆 | 长期·跨会话 | 用户画像：身份/职业/地区/历史咨询类型 | 持久，随对话更新 | mem0 思路（向量+元数据） |
| L3 知识库 | 外部知识·非记忆 | 法律知识库（法条+判例+图谱） | 版本化，支持更新 | RAG 检索 |

**检索装配顺序**：L2 用户画像 → L3 法律知识 → L1 近期上下文 → 全拼进 L0 给 LLM。

## 5. 模型分工

| 任务 | 模型 | 理由 |
|---|---|---|
| 主推理 / 生成 | deepseek-v4-pro | 中文法律理解强 + 成本平衡 |
| 备选 / 次任务 | GLM-5.3 | 容灾 + 结果对比 |
| 改写器 / 评估器 / 轻任务 | flash（deepseek-v4-flash） | 高频调用，省钱 |
| Embedding | 智谱 embedding-3（直连起步） | 无梯子可直连；后续可换 bge-m3（modelscope 本地） |
| Rerank | LLM rerank（省部署） | 后续可换 bge-reranker |

## 6. 技术选型清单

| 模块 | 选型 | 说明 |
|---|---|---|
| 前端 | Next.js 16 | 用户熟悉，流式 SSE 友好 |
| 网关 | FastAPI + WebSocket/SSE | 与 agent 同 Python 栈 |
| Agent 框架 | 轻自研（ReAct 循环） | 书第 1 章套路，不引重框架，便于理解与改造 |
| MCP | Python `mcp` SDK（官方） | 书第 4 章标准，工具可插拔 |
| 关系数据库 | SQLite（SQLAlchemy 抽象）→ PostgreSQL | 开发期 Python 内置零部署；切换只改 DATABASE_URL |
| 向量库 | Chroma（本地起步） | 轻量零部署；经 VectorStore 接口隔离，可切 pgvector/Qdrant |
| BM25 | rank-bm25（纯 Python） | 零部署；后期可切 Elasticsearch |
| 知识图谱 | Neo4j（自带可视化） | 轻量备选：NetworkX + JSON |
| 记忆 | mem0 或自建（SQLite + 向量） | 书第 3 章思路 |
| 评测 | 自建评测集 + LLM-as-judge | 见第 9 节 |
| 包管理 | uv | 用户环境已装 |

## 7. 项目目录结构

```
legal-assistant/
├── frontend/              # ① 前端页面层（Next.js）
│   ├── app/               # 对话页、引用高亮、图谱可视化组件
│   └── components/
├── gateway/               # ② 接入/网关层
│   ├── ws.py              # WebSocket/SSE 流式通道
│   ├── auth.py            # 鉴权 + 会话管理
│   └── llm_router.py      # 多 LLM 路由/容灾（deepseek/GLM）
├── agent/                 # ③ Agent 推理层（大脑）
│   ├── core.py            # ReAct 主循环
│   ├── orchestrator.py    # Agentic RAG 编排器
│   ├── rewriter.py        # ① 改写器：query 改写 + 子问题分解
│   ├── critic.py          # ③ 评估器：证据充分性判断
│   ├── generator.py       # ④ 生成器：答案 + 引用溯源
│   ├── memory/            # 分层记忆 L0-L3
│   │   ├── working.py     # L0 工作记忆
│   │   ├── episodic.py    # L1 情景记忆
│   │   └── semantic.py    # L2 语义记忆（用户画像）
│   └── prompts/           # 提示词模板
├── mcp_tools/             # ④ 工具层（MCP）
│   ├── server.py          # MCP server 入口
│   ├── legal_search.py    # 检索工具（向下调 knowledge/）
│   └── (后续：legal_calculator.py, web_law_lookup.py)
├── knowledge/             # ⑤ 知识/数据层（RAG 基础设施）
│   ├── ingestion/         # 采集 + 清洗 + 分块
│   ├── indexing/          # 向量 + BM25 + 图谱三索引
│   ├── retrieval/         # 混合检索 + RRF + rerank
│   ├── graph/             # Neo4j schema + 图谱查询
│   └── update/            # 增量更新管道（RAG 更新）
├── evaluation/            # 评测集 + 评测脚本
│   ├── dataset/           # 评测数据（gold 标注）
│   └── metrics/           # recall@k / 引用准确率 / 幻觉率
├── data/                  # 原始数据 + 构建好的知识库
└── docs/                  # 本文档
```

**依赖方向（单向，禁止反向 import）**：
`frontend → gateway → agent → mcp_tools → knowledge`
记忆在 agent 内部自洽，评测集独立于运行时。

## 8. 端到端数据流

```
用户提问（frontend）
  → gateway WebSocket/SSE
  → agent 推理层（ReAct 循环）
      → 记忆装配（L2 画像 + L1 近期 + 填 L0 工作区）
      → rewriter（口语→法律检索式 + 子问题分解）
      → 通过 MCP 调 legal_search 工具
          → knowledge 混合检索（向量+BM25+图谱）+ rerank
          → 返回 top-k 法条 + 图谱子图
      → critic（证据够不够？）
          ├─ 不够 → 换 query 再检索（最多 5 轮）
          └─ 够   → generator 生成答案 + 引用溯源 + 免责声明
  → 流式返回 frontend（法条高亮 + 图谱可视化）
```

## 9. 评测集方案

- **数据来源**：LawBench（法律咨询子集）为主，JEC-QA（自带法条解析）补充题面。
- **处理五步**：① 看懂字段 ② 清洗过滤（砍非大陆法/过难题）③ 补标 gold 法条（LLM 辅助 + 人工抽检 30%）④ 时效校验（打"现行有效/已修订/已废止"）⑤ 统一 schema + 领域/难度标签。
- **指标**：检索层 recall@k / MRR / nDCG；生成层 **引用准确率**（核心）、答案正确性、幻觉率、拒答率；效率层 token/延迟。
- **判分**：LLM-as-judge 初筛（结构化 rubric 四项分开打）+ 人工复核 20–30%。
- **规模**：先 30 题跑通，再扩到 100 题；法条带版本号标签，改法时自动定位受影响题目。

## 10. 分阶段路线图

| 阶段 | 内容 | 对应书章节 |
|---|---|---|
| **一期** | 单 agent + 问答 + 混合检索（向量+BM25）+ 基础评测集 30 题 | 第 1、3 章 |
| **二期** | Agentic RAG 多轮编排 + GraphRAG 图谱 + 分层记忆 L2 + 合同审查管线 | 第 3、4 章 |
| **三期** | 多 agent 拆分 + MCP 工具扩展（计算器/联网）+ 评测集扩到 100 题 | 第 4、6、10 章 |
